2026-06-07 13:40:19 [Verify application memory consistency] Sujet 4/ JsonHistoriqueService
On va créer le service JsonHistoriqueService. Ce service conserve l'état courant d'un objet JSON et l'historique de ses modifications (pattern Redux). Il ne stocke pas les états précédents mais les modifications elles-mêmes.

Types de modifications (chacun avec sa classe dédiée héritant d'une classe Modification abstraite) :
- AjouterNoeudObjet : ajouter un objet dans un attribut d'un nœud (identifié par son chemin)
- AjouterNoeudTableau : ajouter un tableau vide dans un attribut d'un nœud (identifié par son chemin)
- ModifierNoeuds : modifier plusieurs attributs primitifs d'un nœud existant (pas de suppression d'attribut, seulement vidage)
- SupprimerAttribut : supprimer un attribut d'un objet identifié par son chemin
- AjouterObjetTableau : ajouter un objet dans un tableau identifié par son chemin
- SupprimerObjetTableau : supprimer un objet d'un tableau identifié par son chemin
- AjouterValeurTableau : ajouter une valeur primitive dans un tableau identifié par son chemin
- SupprimerValeurTableau : supprimer une valeur primitive d'un tableau identifié par son chemin
- DeplacerElementTableau : déplacer un élément d'un index à un autre dans un tableau
- AjouterNoeudQuelconque : usage interne UNDO/REDO uniquement (bloquée dans la méthode publique appliquer())

Chaque modification dispose de :
- appliquer(json) : applique la modification sur le JSON ET conserve l'ancienne valeur (nécessaire à l'inversion)
- inverser() : retourne la modification inverse (l'ancienne valeur est conservée lors du appliquer())

API publique du service :
- appliquer(modification: Modification) : void
- annuler() : void (UNDO)
- retablir() : void (REDO)
- reinitialiser(etatInitial?: JsonValue) : void
- etat : Signal<JsonValue> — état courant (lecture seule)
- etatTypee<T>() : T — état casté dans le type attendu
- journal : Signal<ReadonlyArray<Modification>> — historique chronologique
- peutAnnuler : Signal<boolean>
- peutRetablir : Signal<boolean>

Crée les tests Vitest en instanciation directe (sans TestBed), avec structure describe/it.

Propose des améliorations et des idées à partir de ce besoin

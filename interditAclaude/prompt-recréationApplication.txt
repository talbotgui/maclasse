## BLOC 2 — Initialisation du projet Angular

Crée un projet Angular 21 nommé "maclasse" (SPA offline-first, sans backend) en respectant les conventions définies au BLOC 1.

Structure du projet à mettre en place :
- Routing avec lazy loading et ces routes : /, /competences, /eleves, /cahier-journal, /projets
- Préprocesseur SCSS
- Configuration Vitest pour les tests unitaires
- Un composant racine AppComponent avec <app-barre-superieure> suivi d'un <router-outlet>

Composant BarreSuperieureComponent (partagé, en dehors des routes) :
- Logo et titre de l'application
- Menu de navigation (affiché uniquement si les données sont chargées) : Compétences, Élèves, Cahier journal, Projets
- Bouton de sélection du thème (9 thèmes : Défaut, Cahier, Encre, Préau, Ardoise, Rosier, Récré, Mandarine, Lavande, Menthe)
- Bouton sauvegarde (icône disquette / disquette barrée selon l'état)
- Bouton ANNULER (UNDO) — visible uniquement si des modifications ont été appliquées
- Bouton REFAIRE (REDO) — visible uniquement si des actions ont été annulées
- Bouton imprimer

Variables CSS globales (fichier styles.scss) : 16 variables CSS custom properties sur l'élément racine. Chacun des 9 thèmes surcharge ces variables via un attribut data-theme sur <html>.
Noms des 16 variables : --papier (fond principal), --papier2 (fond secondaire), --carte (fond cartes/panneaux), --carte2 (variante), --encre (texte principal), --encre2 (texte secondaire), --milieu (ton intermédiaire), --discret (éléments peu saillants), --bordure (bordures principales), --bordure2 (variante), --primaire (accentuation principale), --primaire-sombre (hover/focus), --primaire-leger (primaire à 13% opacité), --surbrillance (mise en évidence recherche), --accent (accent secondaire), --erreur (rouge danger).
Jamais de couleur hexadécimale codée en dur : toujours var(--nom-variable).

## BLOC 3 — Modèles de données et ContexteService

Crée le ContexteService dans src/app/services/ avec ces signaux globaux :
- themeActif : signal<IdentifiantTheme> — thème visuel sélectionné, persisté en localStorage('ma-classe:theme')
- sauvegardeAutomatiqueActive : signal<boolean>
- donneesChargees : computed<boolean> — true si le JSON est non vide (utilisé par le guard de route)
- periodeEnCours : computed<Periode | null> — période dont debut <= aujourd'hui <= fin, ou null
- motDePasseChiffrement : signal<string | null> — mot de passe en mémoire vive

## BLOC 5 — SauvegardeService et page d'accueil

Crée le SauvegardeService dans src/app/services/ avec :
- telecharger(motDePasse: string) : chiffre (AES-256-GCM via WebCrypto), compresse (gzip) et télécharge les données en fichier .maclasse
- televerser(fichier: File, motDePasse: string) : déchiffre et charge les données dans JsonHistoriqueService
- chargerDonneesDefaut() : charge src/assets/donnees-defaut.json et initialise JsonHistoriqueService

Logique du bouton "Sauvegarde" dans BarreSuperieureComponent :
- Si données chargées depuis un fichier : sauvegarde automatique active (icône disquette), toutes les 5 minutes si des modifications ont été faites
- Si données créées via "Créer une nouvelle classe" : sauvegarde automatique inactive (icône disquette barrée)
- Au clic : bascule l'état de la sauvegarde automatique
- Au premier clic après "Créer une nouvelle classe" : ouvre une modale pour saisir le mot de passe (avec message d'avertissement : "Ce mot de passe ne peut pas être récupéré, conservez-le précieusement"). Au clic sur "Valider", télécharge le fichier.
- À l'ouverture de la modale, le focus se place sur le champ mot de passe ([mcAutoFocus])

Page d'accueil (AccueilComponent, route /) :
- Si aucune donnée chargée : formulaire de téléversement (champ fichier .maclasse + champ mot de passe) + bouton "Charger" + bouton "Créer une nouvelle classe"
- Si données chargées : message de bienvenue avec résumé (nb élèves, période en cours)
- Au clic sur "Créer une nouvelle classe" : charger les données par défaut et ajuster les dates des séances à la semaine en cours

## BLOC 6 — Données par défaut (assets/donnees-defaut.json)

À partir du fichier Sources/referentiel-complet.json (format plat avec id/parent/text), convertis les données en un tableau de NoeudCompetence imbriqués (IDs UUID générés, couleur pour les nœuds racine).

Génère src/assets/donnees-defaut.json contenant un objet DonneesEnseignant complet avec :

Référentiels :
- Les compétences converties depuis Sources/referentiel-complet.json
- Les jours fériés français de l'année scolaire 2025-2026
- 5 périodes scolaires 2025-2026 : P1 (01/09–17/10), P2 (04/11–19/12), P3 (05/01–13/02), P4 (02/03–10/04), P5 (27/04–03/07)
- statutsAcquisition : { '0': 'Non acquis', '1': 'En cours', '2': 'Acquis' }
- typesContact : { P: 'Père', M: 'Mère', S: 'Structure', F: 'Famille d\'accueil', A: 'Autre' }
- raisonsAbsence : { I: 'Inclusion', O: 'Orthophoniste', PM: 'Psychomotricité', P: 'Psychologue', A: 'Autre' }
- frequencesAbsence : { '0': 'Semaine paire', '1': 'Semaine impaire', '2': 'Chaque semaine' }
- groupes : ['Groupe A', 'Groupe B', 'Groupe C']
- niveaux : ['CP', 'CE1', 'CE2', 'CM1', 'CM2']

Élèves fictifs (une dizaine, inspirés de personnages de BD, âge environ 10 ans) :
Boule (Boule et Bill), Ducobu, Lucky Luke, Cédric (de la BD Cédric), Gaston Lagaffe, Spirou, Tintin, Astérix, Lucky Luke, Natacha, Modeste et Pompon
Données réalistes : contacts (père/mère), cursus (2-3 années), absences récurrentes pour certains, inclusion pour 1-2 élèves.

Séances journalières pour une semaine complète (lundi-vendredi, horaires 8h30-15h30) :
4 à 6 séances par jour, avec disciplines variées, titres, compétences associées et un ou deux élèves/groupes.

Projets (2 ou 3) avec des compétences renseignées pour chaque période.

## BLOC 7 — Page des compétences

Crée le CompetenceService dans src/app/services/ pour la logique de manipulation des compétences (recherche par ID, filtrage, sélection).

Crée la page des compétences (CompetencesComponent, route /competences) :

Structure en deux colonnes :
- Colonne gauche : boutons-pills de filtre par discipline (nœuds de premier niveau). Toutes + chaque discipline. Les disciplines non sélectionnées sont masquées dans la vue centrale.
- Zone centrale (pleine largeur) : deux modes d'affichage (bascule arbre / liste) :
  - Mode arbre : accordéon récursif par niveaux, cases à cocher sur les nœuds feuilles

- Panier (en bas de page) : liste des compétences sélectionnées avec :
  - Bouton "Envoyer au cahier journal" → modale de sélection d'un jour et d'une séance
  - Bouton "Envoyer vers un projet" → modale de sélection d'un projet et d'une période
  - Bouton secondaire "Vider le panier"

RGAA : focus visible sur les boutons arbre/liste et les titres d'accordéon, navigation clavier complète.

## BLOC 8 — Page des élèves

Crée la page des élèves (ElevesComponent, route /eleves) sur le modèle liste + formulaire de droite :

Colonne gauche :
- Liste des élèves (nom + prénom + statut), triée par nom
- Filtres : niveau, groupe, statut (listes déroulantes)
- Bouton "Ajouter un élève" (crée un élève vide et ouvre le formulaire en mode édition)

Colonne droite — formulaire avec accordéons (tous ouverts par défaut) :
- Identité : nom, prénom, date de naissance, statut (liste déroulante), date d'arrivée, droit à l'image, autorisation de baignade — disposition 2-3 colonnes flex
- Inclusion : école nom, école adresse, nom contact, email contact, tél contact, niveau, enseignant, tél enseignant — disposition 2-3 colonnes flex
- Dispositifs et bilans : textarea bilans
- Contacts : cartes flex côte à côte (type, nom, email, téléphone, adresse postale) — bouton "Ajouter un contact"
- Cursus : cartes flex côte à côte (année, niveau, établissement, accompagnement) — bouton "Ajouter une année"
- Absences récurrentes et accompagnements : cartes flex (raison, jour de la semaine, fréquence, heure début/fin) — bouton "Ajouter"

Boutons : "Modifier" (passe en mode édition, focus sur "Annuler"), "Enregistrer", "Annuler", "Supprimer" (avec confirmation).

Libellés de champs en gras dans tous les accordéons.
Les valeurs des listes déroulantes (statut, niveau) doivent être correctement persistées à l'enregistrement.

## BLOC 9 — Page du cahier journal

Crée la page du cahier journal (CahierJournalComponent, route /cahier-journal) :

Panneau gauche (étroit, fixe) :
- Mini calendrier mensuel :
  - Navigation mois précédent / suivant
  - Week-ends grisés
  - Jours fériés grisés
  - Jours hors périodes (vacances) en rouge
  - Jour sélectionné mis en évidence
- Boutons de navigation : Veille, Lendemain, J-7, J+7
- Liste des modèles de séances (petites cartes cliquables — au clic, duplique le modèle dans le jour en cours)
- Liste des projets dont une ProjetPeriode correspond à la période du jour sélectionné (au clic, crée une séance avec titre, élèves et compétences du projet)

Zone centrale :
- En-tête : date complète, numéro de semaine, zone de notes générales
- Liste des créneaux horaires (réordonnables par drag & drop) :
  - Chaque créneau affiche : heure début-fin, discipline, titre, statut
  - Bouton "Ajouter une séance" et bouton "Ajouter un repos" (un repos ne permet de saisir que titre, description, heure début/fin)
- Bilan de fin de journée (en bas, toujours visible)

Panneau droit (1/3 de largeur) — formulaire détaillé de la séance sélectionnée :
- Titre, discipline, heure début, heure fin, statut (radio ou liste)
- Objectifs, déroulement, différenciation
- Composant SelecteurCompetences (autocomplétion : flèches pour naviguer, TAB pour sortir et masquer les propositions, perte de focus masque la liste)
- Élèves/groupes concernés (avec tooltip listant les noms au survol) — boutons "Supprimer" et "Dupliquer" à cet endroit
- Ressources / liens (ajout/suppression de lignes)
- Devoirs, notes personnelles
- Boutons en bas : ANNULER (à gauche), ENREGISTRER (à droite)
- Bouton "Faire de cette séance un modèle" (aligné à droite, taille normale, sans prendre toute la largeur)
- Après ENREGISTRER, si l'état a été annulé (UNDO), le formulaire se rafraîchit avec les nouvelles données annulées

Bouton "Visualiser la semaine" (dans la barre supérieure ou l'en-tête de page) : masque les panneaux gauche et droit, affiche au centre les séances de tous les jours de la semaine (lundi-vendredi) contenant au moins une séance.

Comportement spécial : à l'ajout de la PREMIÈRE séance d'une journée, initialiser automatiquement les notes générales avec un résumé des inclusions et accompagnements des enfants (données issues du formulaire de chaque élève).

## BLOC 11 — Mutualisation du composant sélecteur de compétences

Le sélecteur de compétences (autocomplétion + liste de tags) est utilisé dans le cahier journal (formulaire de séance) et les projets (par période).

Extrait ce composant dans src/app/composants/selecteur-competences/ pour le mutualiser.
L'interface du composant :
- competencesIds = input<string[]>() — ids sélectionnés
- toutesCompetences = input<CompetenceAplatie[]>() — liste à plat des compétences disponibles
- contexteId = input<string>() — suffixe pour les ids HTML (obligatoire si plusieurs instances simultanées)
- competencesModifiees = output<string[]>() — émis à chaque changement de sélection
Navigation clavier : flèches haut/bas pour naviguer dans les propositions, Entrée pour sélectionner, TAB ou Échap pour fermer la liste.
